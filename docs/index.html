easy-worktree

wt is one small zsh function to list, create, jump into and clean up your git worktrees. Further down, the Worktree Forest explains worktrees with animals.

GitHub repo Commands How worktrees work

Install

Needs zsh and git. Docker is optional. Run these two lines, then open a new terminal and type wt.

git clone https://github.com/jeslopcru/easy-worktree.git ~/.easy-worktree
echo '[ -f ~/.easy-worktree/wt.zsh ] && source ~/.easy-worktree/wt.zsh' >> ~/.zshrc

To update later:

git -C ~/.easy-worktree pull
How worktrees work, explained with animals

Once upon a tree

Your project is a big tree in a forest. Deep underground, the tree has memory roots. Every time an animal finishes a piece of work, it buries an acorn in the roots, so the tree remembers it forever.

The tree has branches, and on each branch there can be a little house. One animal lives in each house and works on one job. Owl lives in the big house on top and looks after the main story. Fox is fixing a leak, Rabbit is painting a new room, and Squirrel is checking the acorns.

Every house is its own place with its own mess on the table. But they all hang off the same tree and share the same roots. That is a worktree: one more house on the same tree.

Each house is a folder on your computer. Each branch of the tree is a git branch. The roots are the .git folder, and there is only one.

What is shared, and what is yours

🌳 In the roots: everyone sees it

  • Acorns, the finished work (commits). When Fox buries one, Owl can see it straight away.
  • The list of branches.
  • The secret hiding hole (the stash). Anyone can take what's in it.
  • The map to other forests (remotes like GitLab).

🏠 In each house: only yours

  • The mess on your table, the files you're changing right now.
  • Which branch you live on.
  • Your backpack (.env files). It doesn't come with a new house by itself.
  • Your toys (Docker containers). Every house gets its own set.

Forest rules

🦊

One house per branch

Two animals can't live on the same branch. If Fox is on it, Rabbit has to pick another one.

Git says already checked out.

🐿️

Don't use the hiding hole

The stash is shared by the whole forest. Someone else might grab your things. Bury an acorn marked "not finished" instead.

Make a WIP commit instead of git stash.

🎒

Bring your backpack

A new house starts with an empty hook where the backpack goes. wt new hangs a sign on it pointing to Owl's backpack.

Ignored files are not copied, so .env files get symlinked.

🧸

Put the toys away

If you move out and leave your toys on the path, the other animals trip over them.

Leftover containers keep ports like 5671 busy. wt rm stops them first.

🔨

No hammers

Don't knock a house down yourself. Ask the forest ranger, so the tree knows the house is gone.

Use wt rm, not rm -rf. If you already did, run wt prune.

🌿

Moving out keeps the branch

When an animal leaves, its branch stays on the tree until someone trims it.

Delete it with git branch -D <name> once it's merged.

A day in the forest

This is how Rabbit gets a new job done, from building the house to cleaning up.

  1. 🏗️

    Build a house

    wt new feat/login-page origin/main
  2. 🐰

    Move in

    wt cd login
  3. 🌰

    Work and bury acorns

    git commit
  4. 📮

    Send acorns to the big forest

    git push
  5. 📦

    Move out, toys packed

    wt rm login
  6. ✂️

    Trim the branch

    git branch -D feat/login-page
Reference

Commands

A small zsh function that wraps git worktree. It shows every worktree of the repo you're in. The one you're in is bold with a *, worktrees with uncommitted changes are yellow, clean ones are green, and red means the folder was deleted by hand. Press Tab after wt to complete commands, worktree names and branch names.

$ wt 0 1 changed main ~/code/my-app * 1 0 changed feat/login-page ~/code/my-app/.claude/worktrees/feat-login-page 2 3 changed fix/flaky-tests ~/code/my-app/.claude/worktrees/fix-flaky-tests 3 folder gone ~/code/my-app/.claude/worktrees/old-spike (stale — wt prune)
uncommitted changes clean folder deleted by hand bold * you are here
CommandWhat it does
wtList worktrees with their number, changed-file count, branch and path.
wt new <branch> [base]Create a worktree in $WT_DIR and move into it. Checks out the branch if it already exists, or creates it from base (default: current HEAD). Symlinks the main checkout's .env files.
wt cd <n|name>Move your terminal into a worktree. Use the number from the list, or any part of the path.
wt rm <n|name> [-f]Stop the worktree's Docker Compose project (down -v), then remove it. Refuses if there are uncommitted changes unless you pass -f. Never removes the main checkout. Keeps the branch.
wt pruneForget worktrees whose folder was deleted by hand (shown in red as folder gone in the list). Stops their Docker Compose first. Never touches folders that exist, branches or commits.
wt helpUsage, how to read the list, and examples.

Tab completion

You typeTab suggests
wt <Tab>The commands, each with a short description
wt cd <Tab>Worktree folder names, with the branch each one is on
wt rm <Tab>The same list without the main checkout, then -f
wt new <Tab>Your local branches
wt new feat/x <Tab>Local and remote branches to start from
